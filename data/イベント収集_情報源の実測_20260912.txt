● 選別で踏んだ落とし穴(全部対処済み)
  1. **純粋なスコア順にすると、いこーよが12枠中10を占めて地元の祭りが全部落ちた**。
     「【宮地嶽神社】秋季大祭」「広川かすり祭」「八女のまつり」は子連れ語を持たないので
     スコア8止まりだが、モールにもいこーよにも出てこない**その地域だけの行事**で
     記事としては一番強い。→ **源をラウンドロビンで回し、同じ市区は2件まで**に変更
  2. 会期パーサが 160件中14件を読めていなかった。内訳と対処:
     ・「2026年8⽉4⽇（火）〜16⽇（日）」… **康熙部首**の ⽉(U+2F49)/⽇(U+2F47)。
       個別に置換しようとして**コードポイントを間違えた**(U+2F8Cは「食」)。
       → `unicodedata.normalize('NFKC')` に一括で任せるのが正解
     ・「〜16日」… 終了側が**日だけ**の表記 → 開始の年月を使って補う
     ・「2026年7月上旬〜9月中旬」… 上旬/中旬/下旬 → 5日/15日/25日に寄せる
     ・「2026年見ごろ：9月」… 月だけ → その月いっぱい
     ・「2026年3月〜11月の第2日曜 ※3月8日、4月12日…」… **特定日の列挙**。
       min〜maxのレンジにすると「その間ずっと開催」と誤読するので**日リストとして扱う**。
       かつ ※以降に年が無いため、先頭の「2026年」を既定年にしないと2027年と誤推定した
     ・「2025年以降の開催はありません」「【営業終了】」… **終了済み**として明示的に落とす
     → 結果: 読めない 40件 → **8件**、対象期間にかかるもの 13件 → **32件(2.5倍)**
  3. 商業施設のパスが2系統(/news/event と /event)。揃えると片方が**200のまま0件**になる
  4. 「ワーク ショップ」のように空白入りのタイトルがあるので、キーワード判定は**空白を潰してから**
  5. 「ポケモンしんかラリー」が館ごとに表記ぶれ(『』第2弾スタート！！)で3枠を占めた
     → 記号・第N弾・スタート等を落として正規化してから束ねる

     誤情報なので本文からの推測をやめ、表(<td>)からだけ取る

■ 投稿の型: 週2本に分ける【2026-09-13 ユーザー確定】
════════════════════════════════════════
同じ収集データから**投稿のタイミングで対象期間と見出しを変えて2本出す**。

  ① 平日に出す「次の週末」版
       対象 = 次の土日(連休ならその全日)
       見出し = 「9/19(土)〜9/23(水) の週末イベント◯選」
       目的 = **予定を立ててもらう**。短期開催・予約が要るものが主役になる
       出す日 = 火〜水(ゆめはぴも週末の4日前に出していた)

  ② 土日に出す「すぐ行ける」版
       対象 = その日〜翌日
       見出し = 「9月14日(月) すぐ行けるおでかけ◯選」
       目的 = **今から動いてもらう**。長期開催の展示・常設が主役になる
       仕掛け = カードとキャプションに**残り日数**を出す
                ★ = 7日以内に終わる / (あと◯日) = 8〜14日
                ⚠★を14日以内に付けると「今週で終わる」という文言と矛盾する(2026-09-13に直した)

  コマンド:
    ① python tools/week_events.py --from 2026-09-19 --to 2026-09-23 --n 12 --detail
       python tools/event_carousel.py --n 12 --title "9/19(土)〜9/23(水) の週末イベント"
    ② python tools/week_events.py --from <当日> --to <翌日> --n 12 --detail
       python tools/event_carousel.py --n 12 --title "◯月◯日(◯) すぐ行けるおでかけ"

■ 2026年9月の連休【要注意】
  **シルバーウィークは 9/19(土)〜9/23(水) の5連休**(11年ぶり)。
    9/21(月)=敬老の日 / 9/22(火)=**国民の休日**(祝日に挟まれた平日) / 9/23(水)=秋分の日
  → 「次の週末」版の対象期間は **3連休ではなく5連休(9/19〜9/23)** で取る。
    3連休で取ると9/22・9/23のイベントを丸ごと落とす

■ カルーセルの仕様(tools/event_carousel.py)
  1080x1350(インスタのフィード最適)・14枚 = 表紙 + 12件 + 締め
  ・ポスターは**縮小のみでトリミングしない**。カード下部に出典(主催者/施設)を必ず出す
  ・**IPコラボ(ポケモン/プリキュア/サンリオ/ちいかわ等)はポスターを貼らない**
    → テキストカード「キャラクターの画像は権利の都合で載せていません」に差し替え
  ・⚠絵文字(📅🕐📍🅿)は **Meiryoに字形が無く□の豆腐になる**。日本語ラベル(日程/時間/場所/料金/駐車)で組む
  ・⚠「いこーよ」「県公式」は**集約サイト名**。会場欄と出典欄に出してはいけない(市区で代替)
  ・YouTubeは静止画カルーセルが投稿できない → **14枚をスライドショー動画にしてShorts**(1枚3.5秒=約49秒)

■ 重大バグ: 県公式のURLが全件1つズレていた【2026-09-13 修正】
════════════════════════════════════════
tools/event_watch.py の collect_tiles() が「タイトルを起点に前後へ遡る」方式で、
back=2200字 / fwd=500字 の窓から /event/ のidを拾い **ids[-1]** を採用していた。

実際のHTMLは
  <li class="o-digest--tile__item">
    <a class="o-digest--tile__anchor" href=".../event/XXXX">
      <div class="…__image-box"> …favorite-button… (ここが長い) …
      <dl class="…__date"><dd>会期</dd></dl>
      <h2 class="…__title">タイトル</h2></div>
      <p class="…__description">説明</p></a></li>
で、**自分のリンクは画像ブロックのぶん2200字より前**にあるため back には1件も入らず、
fwd に入る**次のタイルのid**を毎回拾っていた。つまり全件ちょうど1つ後ろを指していた。

  発覚の経緯: 「パンダコパンダ展(北九州市漫画ミュージアム)」の詳細を開いたら
             **糸島市有田**が返ってきた。「放生会」のidも実際は隣の「柳川ひまわり園」だった。

修正: **<li class="o-digest--tile__item"> のブロック単位でパースする**。
      ブロック内なら id・タイトル・会期・説明・画像が必ず揃う。
      idは href と `:tourism-attraction-id="XXXX"` の2箇所にあるので**一致を検算**し、
      違うものは捨てる。検算として一覧のタイトルと詳細ページの <title> の一致も確認した。

⚠教訓: **「起点から前後N字」方式は要素の並びと長さに依存するので使わない**。
       繰り返し単位(<li>等)で切ること。0件になる失敗はすぐ気づくが、
       **1つズレる失敗は件数が合うので気づかない**(2026-09-11に0件で踏んだのと同じ箇所)

■ 県公式の会場情報【2026-09-13 実装】
  詳細ページは <th>ラベル</th><td>値</td> の表。取れるもの:
    住所(〒付き) / 電話番号 / 開催日 / 駐車場 / アクセス情報 / ウェブサイト(値は href 側)
  ・住所から**市区**を取って city に入れる(検索ワードが弱くなる問題の解消)
  ・住所の末尾が会場名になっていることが多い → 町名+番地を1回で削って残りを place に
    ⚠文字クラスで番地を消すと「番地」の"地"が効いて**地行浜→行浜**と町名の頭を食う。
      `^[^\s]*?[0-9][0-9\-丁目番地号の]*\s*` でまとめて削る
  ・ウェブサイト(公式)が取れたらキャプションのリンクはそちらを出す(クロスロードより親切)
